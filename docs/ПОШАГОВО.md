# Пошагово, с нуля (Windows)

Ниже — путь от чистого компьютера до Су-34 в игре. Первые три шага делаются
один раз и занимают вечер (в основном из-за скачивания Unity). Дальше сборка
мода — это две команды.

> Всё, что связано с Unity и Windows, нужно делать на своём ПК. В песочнице,
> где готовился репозиторий, нет ни Windows, ни Unity, ни файлов игры, поэтому
> DLL и asset bundle собираются у вас.

---

## Шаг 0. Что установить

| Что | Где | Зачем |
|---|---|---|
| VTOL VR | Steam | игра |
| VTOL VR Mod Loader | Steam, app **3018410** | загрузчик модов; ставить на тот же диск, что игру |
| .NET SDK 8 | dotnet.microsoft.com | собрать `Su34Mod.dll` |
| Unity Hub + Unity **2020.3.49f1** | unity.com | собрать asset bundle |
| AssetRipper | github.com/AssetRipper/AssetRipper/releases | развернуть игру в Unity-проект |
| Git (по желанию) | git-scm.com | обновлять репозиторий |

Ещё подпишитесь в Workshop модлоадера на **VTOLAPI** — без него внешние
самолёты получают кривые шейдеры.

---

> **Если уже стоит Unity 2022.3 (или новее) — для бандла он не подойдёт.**
> VTOL VR работает на Unity **2020.3.x**, и asset bundle, собранный в более
> новом редакторе, игра не загрузит: в логе будет «built with a newer version
> of Unity», а самолёт окажется невидимым. Нужен именно **2020.3.49f1** —
> последний патч ветки (changeset `18249dd5551b`), на нём собрана текущая
> версия игры и на нём собирает сообщество. Он ставится рядом с 2022.3 и
> ничего не ломает: **Installs → Install Editor → вкладка Archive →
> 2020.3.49f1**, либо прямая ссылка `unityhub://2020.3.49f1/18249dd5551b`
> (вставить в адресную строку браузера). Открывать проект нужно именно этой
> версией. Для `Su34Mod.dll` версия Unity не важна вообще — он собирается
> через dotnet. Билдер к тому же сам останавливается, если редактор не
> 2020.3.x, и пишет это в консоль.

## С какими версиями это работает

| Компонент | Версия, под которую собран репозиторий |
|---|---|
| VTOL VR | **1.13.4f1** (сентябрь 2026) |
| VTOL VR Mod Loader | **6.10.x** (ставится из Steam) |
| Unity для бандла | **2020.3.49f1** — игра перешла на неё в хотфиксе 1.12.6f1 |
| .NET SDK | 8, целевая платформа `net472` |

Три правила, которые снимают 90% вопросов «а почему не работает»:

* **DLL компилируется против `Assembly-CSharp.dll` из вашей установки.** После
  обновления игры её нужно пересобрать: старый DLL может не найти методы,
  которых больше нет.
* **Бандл зависит только от версии Unity, а не от версии игры.** Пока в
  `Player.log` стоит `2020.3.49f1`, ранее собранный бандл годится.
* **Если после обновления игры кастомные самолёты перестали грузиться у всех**
  (ванильные при этом работают) — это чинится в мод-лоадере, а не в этом
  репозитории. Быстрая проверка: подпишитесь в Workshop на любой готовый
  самолёт, например F-16, и попробуйте вылететь на нём.

## Шаг 1. Проверить версию Unity

1. Запустите VTOL VR хотя бы раз.
2. Откройте
   `%USERPROFILE%\AppData\LocalLow\Boundless Dynamics, LLC\VTOLVR\Player.log`
   (или `...\steamapps\common\VTOL VR\Player.log`).
3. Третья строка: `Initialize engine version: 2020.3.49f1 (...)`. Это и есть
   нужная версия. Если у вас другой патч 2020.3 (например, 2020.3.48f1) —
   ставьте ровно тот, что в логе: бандл, собранный **более новым** патчем,
   чем плеер игры, может не загрузиться.

## Шаг 2. Развернуть игру в Unity-проект (один раз)

Половина этого шага — механическая работа с файлами, и именно на ней ломаются
руки. Поэтому она отдана скрипту, а в Unity остаётся только то, что делается
из редактора.

### 2.1. Выгрузить игру AssetRipper'ом

1. Запустите `AssetRipper.GUI.Free.exe`.
2. Перетащите в него папку `...\steamapps\common\VTOL VR`.
3. Дождитесь окончания разбора, затем `Export > Export All Files` и укажите
   **пустую** папку, например `D:\RipperExport`. Выгрузка идёт долго
   (20–40 минут) и занимает 20–30 ГБ.

### 2.2. Собрать из выгрузки Unity-проект

В PowerShell из корня репозитория:

```powershell
.\tools\prepare_unity_project.ps1 -Export "D:\RipperExport" -Project "D:\VTOLVR_Project"
```

Скрипт проверит игру, напечатает версию Unity из `Player.log`, скопирует
`ExportedProject` в `D:\VTOLVR_Project` (без `AuxiliaryFiles`), удалит
`Assets\Plugins`, положит туда `Assets\Su34` из репозитория, скопирует модель,
её `.mtl` и текстуры в `Assets\Su34\Models`, затем создаст `Assets\Plugins`
заново и скопирует шесть нужных DLL из вашей установки игры. В конце он
перечислит, что осталось сделать в Unity.

Если игра стоит не в стандартном месте, добавьте
`-GamePath "E:\SteamLibrary\steamapps\common\VTOL VR"`.

### 2.3. Доделать в Unity (руками)

1. Unity Hub → **Add** → `D:\VTOLVR_Project`, открыть редактором
   **2020.3.49f1**. Первый импорт — 10–40 минут, это нормально. Если
   предлагает «Enter Safe Mode» — выберите **Ignore**.
2. Package Manager → установить `TextMeshPro` (на вопрос об импорте примеров —
   «No Thanks»), `XR Plugin Management`, `2D Sprite`, `Input System`.
3. Из SteamVR Plugin (Asset Store) импортировать плагин, **сняв** галочку с
   `SteamVR > Input > Plugins > JSON.NET > Valve.Newtonsoft.Json.dll`.
4. `Assets > Reimport All`. Ошибок быть не должно; предупреждения можно
   игнорировать.

Если Unity всё же ругается на `ControlMapper.cs` — в официальной инструкции
(https://vtolvr-mods.com/docs/vtolvr/asset-ripper/) написано, какую строку
закомментировать.

## Шаг 3. Собрать asset bundle

1. **0 - Copy model + textures into Assets** — скопирует `assets/model/*.obj|*.mtl`
   и `textures/*.png` в `Assets/Su34/Models`. Делается автоматически при сборке,
   отдельный пункт нужен, только если хочется посмотреть модель в Unity.
2. **0b - Check setup**. Билдер сам ищет донора в порядке приоритета:
   **EF-24G → T-55 → F/A-26B**. В консоли будет строка вида
   `[Su-34] donor: EF-24G (Assets/Resources/vehicles/EF-24G.prefab), crew seat rigs: 2`.
   * `crew seat rigs: 2` — всё хорошо, второй игрок сможет сесть.
   * `crew seat rigs: 1` — выбран одноместный F/A-26B: мод полетит, но
     вдвоём — нет. Нужен DLC EF-24G или T-55 (и повторный экспорт игры).
   * Ничего не найдено — поправьте путь вручную: константа
     `DonorPrefabOverride` в `Assets/Su34/Editor/Su34BundleBuilder.cs`
     (пустая строка = автопоиск).
3. **1 - Dump donor hierarchy** — создаст `Su34_donor_hierarchy.txt` со всеми
   объектами донора. Полезно, если хочется точно настроить, что скрывать.
4. **2 - Build prefab + asset bundle**. В конце в консоли будет
   `[Su-34] DONE`. В папке репозитория `mod\` появятся `su34` и
   `build_report.txt`.

## Шаг 4. Собрать DLL мода и поставить в игру

Из корня репозитория в PowerShell:

```powershell
.\tools\build.ps1                 # соберёт Su34Mod.dll в mod\
.\tools\install.ps1               # скопирует mod\* в игру
```

Если игра стоит не в стандартном месте:

```powershell
.\tools\build.ps1   -GamePath "D:\Steam\steamapps\common\VTOL VR"
.\tools\install.ps1 -GamePath "D:\Steam\steamapps\common\VTOL VR"
```

Можно и вручную: папку `mod` переименовать в `Su-34` и положить в
`...\steamapps\common\VTOL VR\@Mod Loader\Mods\`.

Либо вообще без консоли: в Unity после шага 3 выберите
**VTOL VR → Su-34 → 3 - Build DLL and install into the game** — он сам вызовет
`build.ps1 -Deploy`.

## Шаг 5. Запуск

1. Запустите **VTOL VR Mod Loader** из Steam.
2. Включите `VTOLAPI` и `Su-34 Fullback`, нажмите Play.
3. В игре: выбор пилота → список самолётов → **Su-34**.
4. Если что-то не так — `F10` в полёте и лог игры (см. ниже).

### Как полететь вдвоём

Бок о бок в VTOL VR уже сделано до нас: мод **AH-6 Little Bird** (DankuwOs) —
двухместный вертолёт, где пилоты сидят рядом, и он требует AH-94. Механика та
же, что у нас: берётся двухместный префаб донора, его посадочные места
переносятся на новые кресла, а сам мод грузит префаб из бандла. Ничего
экзотического в этом нет.

1. Убедитесь, что `0b - Check setup` показал `crew seat rigs: 2` (донор EF-24G
   или T-55). Если `1` — второго места не будет, нужен DLC и повторный экспорт.
2. В **редакторе миссий** поставьте спавн игрока и в свойствах выберите
   **2 slots** вместо 1. По умолчанию там 1 — именно поэтому «второй не
   заходит».
3. Запустите миссию по сети: второй игрок выбирает тот же борт и садится
   справа (штурман). В одиночной игре место переключается кнопкой, как в T-55.
4. Если второй игрок не может сесть: проверьте, что в `build_report.txt` есть
   строка `two crew seats aligned side by side` и `seat rig wrapped in marker`.

#### Если голова сидит не там

Кресла стоят на координатах, снятых с самого меша (`-0.52 / +0.52` по бортам,
`y 1.45`, `z 6.30`). Но то, куда игра кладёт голову игрока, зависит от того,
как устроен посадочный риг донора, и увидеть это отсюда невозможно. Поэтому
смещение каждого кресла вынесено в `su34.cfg`:

```ini
seatpilotx = 0.00    # вправо (+), влево (-)
seatpiloty = 0.00    # вверх (+), вниз (-)
seatpilotz = 0.00    # вперёд к носу (+), назад (-)
seatwsox = 0.00
seatwsoy = 0.00
seatwsoz = 0.00
```

Поменяли число — перезапустили миссию, пересобирать бандл не нужно.
Консоль при этом пишет `seat Su34_SeatPilot moved by (...)`, так что видно,
что смещение применилось.

### Что делать с кабиной

Расставлять МФД, РУД и HUD руками не надо. Они приезжают из префаба донора
вместе с логикой, а билдер раскладывает их по креслам: передняя станция
донора — на левое кресло (пилот), задняя — на правое (штурман). Подробности —
в `unity/README.md`, раздел «Кабина».

Первое, что стоит сделать в игре: сесть в левое кресло и посмотреть, попадают
ли приборы в поле зрения. Если панель слишком далеко или слишком близко —
крути `seatpilotz` в `su34.cfg` (кресло едет к панели). Так же для штурмана.
Приборную панель и МФД сдвигать отдельно не нужно.

### Как подкрутить лётную модель

Префаб наследует массу, тягу и аэродинамику донора, поэтому при сборке и при
каждом спавне мод перезаписывает их реальными числами Су-34 (см.
`mod/su34.cfg`):

| Параметр | Значение | Откуда |
|---|---|---|
| `emptymasskg` | 22 500 | пустой Су-34; нормальный взлётный 39 000, максимум 45 000 |
| `thrustabn` | 264 780 Н | 2 × АЛ-31ФМ1 по 13 500 кгс на форсаже |
| `thrustdryn` | 161 810 Н | 2 × 8 250 кгс без форсажа |
| `wingaream2` | 62.0 | площадь крыла |
| `wingspanm` | 14.7 | размах |
| `glimit` | 7.0 | +7 g |

Числа из файла побеждают зашитые в код — можно править без пересборки.
В `Output.log` после спавна появляется блок `--- Su-34 flight model ---`: там
видно, какие поля нашлись, что было до и что стало. По нему и понятно, где
донор отличается от ожидаемого. Полный дамп всех полей — пункт меню
`3 - Dump flight model to a file` в Unity: он пишет `Su34_flightmodel.txt`
в корень проекта.

Что подкручивать, если полетит «не так»:

* **тяжело разгоняется** — `thrustabn` вверх на 5–10%;
* **слишком резкий по тангажу** — `pitchauthority = 0.9`;
* **разваливается на перегрузке** — `glimit` вниз (7.0 и есть реальный предел);
* **планирует как кирпич** — `wingaream2` вверх (62 м² — площадь трапеции;
  с наплывами эффективная больше, можно попробовать 65–68).

## Если не работает

| Симптом | Что смотреть |
|---|---|
| Самолёта нет в списке | В логе `[Su-34] asset bundle not found` → в папке мода нет файла `su34`; `[Su-34] the game did not register` → бандл собран без `ExternalVehicleInfo`/неверное имя префаба |
| Самолёт есть, но невидимый | Бандл собран из чужой версии Unity; пересоберите в 2020.3.x, как в шаге 1 |
| Не видно кабины / всё серое | Не установлен VTOLAPI, либо шейдеры донора не прошли `FixShaders` |
| Мод не загружается, в логе `patch '...' could not be applied` | Игра обновилась и переименовала метод — это одна фича, остальное работает; напишите issue с номером версии игры |
| Игра падает при загрузке бандла | Проверьте, что модель не содержит скриптов и что бандл собран под `StandaloneWindows64` |
| Второй игрок не может сесть в Су-34 | `crew seat rigs` в логе = 1 (донор F/A-26B) → нужен DLC EF-24G/T-55; либо у спавна в редакторе стоит 1 слот вместо 2 |

Лог игры: `%USERPROFILE%\AppData\LocalLow\Boundless Dynamics, LLC\VTOLVR\Player.log`
(ищите строки с `[Su-34]`).
