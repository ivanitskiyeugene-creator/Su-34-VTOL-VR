# Брифинг: что прислать, чтобы завтра работа пошла быстро

Это не инструкция «как сделать мод» (она в `ПОШАГОВО.md`), а список входящих
данных: модель, характеристики, вооружение, референсы кабины. Ниже — в каком
виде их удобно отдать, чтобы не терять день на переделку.

---

> Полный список данных (габариты, массы, двигатели, ЛТХ, управление, оружие,
> авионика) — в **`docs/ТЗ.md`**. Этот бриф — про то, как прислать модель и
> референсы; ТЗ — про цифры.

## 0. Итог короткого опроса (уже известно)

| Вопрос | Ответ |
|---|---|
| DLC | **EF-24G есть** → мод собирается двухместным, второй игрок садится справа |
| Формат модели | **OBJ** → проверяю геометрию здесь, до Unity |
| Источник модели | **Igna's NPC Pack** (Workshop id `3683868201`, автор ItsIgna): меш Su-34 Fullback, извлекаем скриптом |
| Кредиты | добавляет автор мода (не я) |

Значит, «чужая модель от художника» отпадает: работаем по пути
«извлечение из пака → проверка → подстановка». Порядок в разделе 1.

## 1. Внешняя 3D-модель

### Шаг 1: найти пак и вытащить меш

```powershell
pip install UnityPy

# 1) найти, в каком из подписанных паков вообще есть Су-34.
#    Одна команда на всю папку подписок — можно указать и ...\workshop\content
python tools/su34_model/extract_from_bundle.py --scan ^
    "C:\Program Files (x86)\Steam\steamapps\workshop\content\3018410"

# 2) что лежит внутри найденного пака (пришлите этот вывод)
python tools/su34_model/extract_from_bundle.py --list ^
    --bundle "C:\...\3018410\<id>"

# 3) экспорт нужного меша + текстур
python tools/su34_model/extract_from_bundle.py --mesh su-34 ^
    --bundle "C:\...\3018410\<id>" --out incoming/su34_pack.obj
```

`--scan` печатает по строке на пак: сколько в нём мешей, сколько совпало с
`su-34` и самый крупный меш. По этой таблице сразу видно нужный id, и не надо
перебирать полсотни папок. Если совпадений ноль — запустите с `--mesh su`
или `--mesh 34`: в паках имена бывают `Su34_body`, `Su-34_airframe`, `Fullback`.

Папка с id пака открывается и вручную: Мастерская → подписка →
«Просмотреть в папке». Id — те же цифры, что в адресе страницы пака
(`...?id=<id>`).

Если `--list` не показывает ни одного меша с «su34» в имени — пришлите весь
вывод, разберёмся по названиям (там бывают `Su-34`, `Su34_airframe`,
`Fullback` и т. п.).

### Шаг 2: проверка и нормализация (это делаю я)

```bash
python tools/su34_model/import_check.py incoming/su34_pack.obj
```

Скрипт сам скажет, в каких осях модель, где нос, в каких единицах масштаб, есть
ли UV и материалы, разбиты ли рули и створки. Дальше:

```bash
python tools/su34_model/import_check.py incoming/su34_pack.obj \
    --up z --forward -y --auto-scale --center-x --out assets/model/su34_imported.obj
```

### Что должно быть в паке, чтобы всё пошло гладко

1. **Отдельные объекты** для подвижного: `aileron_L/R`, `flap_L/R`,
   `elevator_L/R`, `rudder_L/R`, `canard_L/R`, `gear_door_*`, `airbrake_L/R`.
   Если всё слито — рули будут «мёртвой» геометрией.
2. **UV и текстуры** — чтобы камуфляж остался авторским.
3. **Нормали** (в OBJ почти всегда есть).
4. **Ориентация**: типично Unity-пак = Y вверх, нос в +Z, метры — тогда
   `--up y --forward +z` и без `--auto-scale`.

### Формат: что годится

| Формат | Годится? | Комментарий |
|---|---|---|
| **OBJ + MTL (+ PNG-текстуры)** | **лучший** | я читаю его здесь: проверяю габариты, оси, материалы, разбивку |
| glTF / GLB | хорошо | читаемо, но OBJ проще; glTF пришлите, если в нём текстуры упакованы |
| FBX | можно | для сборки в Unity — нормально; но в моей песочнице его не открыть, поэтому проверку геометрии придётся делать по скриншотам и `import_check.py` уже после конвертации в OBJ |
| .blend | нет | сохраните из Blender в FBX или OBJ |

Если модель в **сантиметрах** и **Z вверх** (типичный экспорт из Blender) — это
не проблема, просто скажите. Скрипт `tools/su34_model/import_check.py`
определяет это сам и пересобирает файл в оси VTOL VR:

```bash
python3 tools/su34_model/import_check.py incoming.obj --up z --forward -y --auto-scale --center-x --out assets/model/su34_imported.obj
```

Он же скажет, если модель зеркальная или длина не 23–25 м.

### Что должно быть в файле

1. **Оси и масштаб.** В итоге: метры, нос в **+Z**, верх в **+Y**. Если исходник
   другой — ладно, но напишите, какой (например: «Blender, Z вверх, нос в −Y,
   сантиметры»).
2. **Отдельные объекты для подвижного:**
   `aileron_L/R`, `flap_L/R`, `elevator_L/R` (стабилизаторы), `rudder_L/R`,
   `canard_L/R`, `gear_door_*`, `gear_*`, `airbrake_L/R`, `refuel_probe`.
   Если всё слито в один меш — скажите, это будет «мёртвая» геометрия: рули
   визуально есть, но не двигаются.
3. **Материалы** с именами на `Su34_` (например `Su34_Camo`, `Su34_Glass`,
   `Su34_Metal`). Так я потом смогу заменить текстуры, не трогая геометрию.
4. **UV-развёртка** — любая вменяемая (атлас или тайлинг). Если её нет, скажите:
   сделаю блочную проекцию сам, но на камуфляже будут швы.
5. **Кокпит.** Если во внешней модели есть внутренняя часть фонаря/переплёта —
   хорошо. Интерьер кабины мы всё равно строим отдельно по референсам.
6. **Автор и разрешение.** Кредит автору пака — обязателен (это вы и
   планировали). Разрешение на публикацию — отдельно: бесплатное в Мастерской
   не значит «без авторского права». Подробности и чек-лист —
   `docs/АТРИБУЦИЯ.md`. Для себя мод собирается в любом случае.

### Проверка, которую я прогоняю сразу

```
objects / triangles / materials, UV, нормали
габариты и длина, определение оси и носа
зеркальность, масштаб, вырожденные треугольники
есть ли отдельные рули/закрылки/створки шасси
```

## 2. Точные характеристики

Заполните таблицу (можно просто списком, единицы указывать). Слева — поле в
моде, справа — куда оно пойдёт.

| Параметр | Значение | Куда идёт |
|---|---|---|
| Длина, м | | контроль модели |
| Размах, м | | контроль модели |
| Высота (шасси выпущены), м | | контроль модели |
| Площадь крыла, м² | | расчёт нагрузки, полётная модель |
| Пустая масса, кг | | `masskg` в `su34.cfg`, инерция |
| Нормальная взлётная, кг | | масса по умолчанию |
| Максимальная взлётная, кг | | ограничение нагрузки в конфигураторе |
| Тяга, кН (сухой / форсаж) на двигатель | | `thrustscale` (или прямая подмена `maxThrust`) |
| Макс. скорость, км/ч (у земли / на высоте) | | проверка после настройки |
| Практический потолок, м | | проверка |
| Скороподъёмность, м/с | | проверка |
| Перегрузка, g (эксплуатационная / разрушающая) | | множители `pitchauthority` и т.п. |
| Запас топлива, кг | | если донор умеет топливо |
| Длина разбега/пробега, м | | шасси, тормоза |
| Кол-во точек подвески | | оружие (см. ниже) |

Если каких-то цифр нет — присылайте то, что есть: остальное я возьму из
открытых источников и помечу как оценку.

| Законцовки (L/R) | | | |
| Центральная / фюзеляж | | | |

Аналоги в игре, из которых собирается комплект: `AIM-9`, `AIM-120`, `AIM-7`,

Су-34** и в каком количестве. Остальное — моя работа: прописать точки, массу,

## 4. Референсы кабины

Референсы нужны не «пачкой», а по списку — так я не пропущу угол. Для каждого
кадра подпишите, что на нём (или просто назовите файлы по номерам ниже).

1. **Общий вид кабины** вперёд из проёма (видно оба кресла, панель, ИЛС).
2. **Приборная панель слева** (место пилота) — крупно, чтобы читались надписи.
3. **Приборная панель справа** (место штурмана) — крупно.
4. **Козырёк + ИЛС** — как стоит, куда светит, размеры стекла.
5. **Центральная консоль** между креслами (пульт, РУДы).
6. **Левый и правый боковые пульты** (по кадру на каждый).
7. **Кресло** (К-36ДМ): чашка, спинка, подголовник, ремни, ручки катапульты.
8. **Потолок / задняя перегородка** (если есть кадры).
9. **Переплёт фонаря** снаружи и изнутри: сколько дуг, где замки, где
   форточки.
10. **МФД**: сколько экранов, какого размера, какие страницы обычно выводят.

Отдельно — **размеры**, если найдёте (хотя бы приблизительно):

* расстояние между центрами кресел (у Су-34 места бок о бок, не тандем);
* высота глаз над полом кабины;
* вынос приборной панели от глаз и угол её наклона;
* высота порога фонаря над полом;
* ширина кабины по внутренним стенкам.

Без цифр я построю по пропорциям с референсов — это нормально, но с цифрами
получится «как в жизни» с первого раза.

## 5. Что произойдёт, когда данные придут

1. `import_check.py` — проверка осей/масштаба/материалов, нормализация в
   метры и +Z.
2. Разбивка рулей/закрылков/створок на отдельные объекты (если не разбито),
   проверка вырожденных треугольников, `inspect_obj.py`.
3. Пересборка кабины по референсам: геометрия кресел, панели, пультов, ИЛС,
   остекление и переплёт — на наших координатах (пилот слева, штурман справа).
4. Текстуры под новую модель (камуфляж, надписи, стёкла).
5. Полётная модель и вооружение: `su34.cfg`, таблица подвесок, тесты в редакторе.
6. Unity: `Copy model → 0b Check setup → 2 Build` и первый запуск в игре.
