# Модель Су-34: генератор и подготовка своего меша

## Что лежит в репозитории

```
tools/su34_model/mesh_lib.py        мини-библиотека: лофт, крылья по профилям, цилиндры, экспорт OBJ
tools/su34_model/generate_su34.py   сборка всего самолёта из чисел (станции фюзеляжа, крыло, оперение, ...)
tools/su34_model/render_preview.py  софтверный рендер (numpy + Pillow) для превью без Unity
assets/model/su34.obj              результат: ~7 200 треугольников, 12 материалов
assets/model/su34.mtl              материалы в терминах MTL (Kd/Ns/d)
docs/model/*.png                   превью: четверть, сбоку, сверху, спереди
```

Сгенерировать и посмотреть заново:

```bash
python3 tools/su34_model/generate_su34.py
python3 tools/su34_model/render_preview.py
```

Скрипт рендера пишет `docs/model/su34_preview.png` — контактный лист из четырёх
видов. Никаких GPU и Unity для этого не нужно.

## Геометрия: как считается

* Оси — юнитивские: **+X вправо, +Y вверх, +Z нос**. Метры, 1:1.
* Фюзеляж — лофт по 26 сечениям (таблица `fuselage_stations`: z, полуширина,
  полувысота, центр по Y, показатель суперэллипса). Нос (z ≥ 9.2) — отдельная
  часть с материалом радиопрозрачного обтекателя.
* Кабина — проём в фюзеляже (пропускаются квады верхнего сектора между
  z 3.3…7.75), внутри тёмный «стакан», сверху полусфера остекления с рамами.
  Фонарь полупрозрачный (alpha 0.30 в MTL): в Unity его надо заменить на
  материал со стеклянным шейдером или оставить как есть — для внешнего вида
  хватает.
* Крыло, ПГО, кили, стабилизаторы, рули, закрылки — функция `lifting_surface`
  по профилю NACA с линейным сужением. Кромки и хорды считаются функциями
  `wing_le/wing_chord`, поэтому рули сами садятся на заднюю кромку.
* Мотогондолы — отдельные суперэллипсы, сопла, обечайки воздухозаборников,
  «лепестки» форсажа.
* Шасси: носовая стойка с двумя колёсами, основные — двухколёсные тележки;
  двери ниш.
* Пилоны: 3 под крылом + 1 под воздухозаборником на борт, плюс законцовочные
  контейнеры.
* `Mesh.orient(part, ref)` автоматически разворачивает треугольники наружу
  относительно опорной поверхности — не нужно вручную следить за порядком
  обхода вершин.

## Свой hi-poly меш

1. **Лицензия.** Берите модель с CC-BY, купленную или заказанную. Выдранные из
   War Thunder / DCS ассеты использовать нельзя: это нарушение лицензий и
   правил публикации модов.
2. **Масштаб и оси.** Длина 23.3 м, размах 14.7 м. В Blender: `Forward = -Z`,
   `Up = Y`, `Apply Transform`, масштаб 1.0. В Unity нос должен смотреть в +Z.
3. **Разрезка поверхностей.** Каждый руль/закрылок/створка — отдельный объект
   с origin на оси вращения:

   | Объект | Ось |
   |---|---|
   | `aileron_L/R`, `flap_L/R` | X |
   | `elevator_L/R` | X |
   | `rudder_L/R` | Y |
   | `canard_L/R` | X |
   | `gear_door_*` | Z |

4. **UV и материалы.** Один атлас 4K на весь самолёт, PBR-материал
   (Metallic/Smoothness). Имена материалов лучше начинать с `Su34_`.
5. **Импорт.** `Assets/Su34/Models/Su34_HighPoly.fbx`, Model → Scale Factor 1,
   Read/Write Enabled, Generate Lightmap UVs, Rig → None.
6. **Подмена в билдере.** В `unity/Assets/Su34/Editor/Su34BundleBuilder.cs`
   в `AttachModel` замените

   ```csharp
   var modelAsset = AssetDatabase.LoadAssetAtPath<GameObject>(ModelObjPath);
   ```

   на путь к вашему префабу (или создайте префаб из FBX и положите его в ту же
   папку, поменяв `ModelObjPath`).

## Куда это встаёт в игре

`Su34_Visual` — просто дочерний объект под корнем префаба. Всё «мясо» (масса,
коллайдеры, шасси, кабина, MFD, оружие) остаётся от донора F/A-26B, поэтому
самолёт сразу летает, стреляет и садится на палубу. Внешние рендереры донора
билдер отключает, кабину — оставляет.
