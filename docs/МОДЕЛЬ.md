# Модель Су-34

## Что сейчас стоит в моде

Внешний вид собран из **модели bohmerang** (Sketchfab, свободная загрузка,
см. `docs/АТРИБУЦИЯ.md`): `assets/model/su34_donor.obj` + `su34_donor.mtl` +
текстуры `donor_basecolor.png`, `donor_normal.png` и `donor_metalsmooth.png`.

| Параметр | Значение |
|---|---|
| Треугольников | 33 582 (планер 15 063, кабина 5 749, шасси выпущено 11 824) |
| Узлы OBJ | `Su-34-airframe`, `Su-34-canopy`, `Su-34-cockpit`, `Su-34-hud`, `Su-34-instrGlass`, `Su34_GearOff`, `Su34_GearOn`, `Su34_GearOnLight` |
| Ориентация | `+z` — нос, `+x` — правый борт, `+y` — вверх (пересчитано `tools/donor_frame.py`) |
| Выравнивание | масштаб 1.015, нос на z = 11.62, низ на y = 0 |
| Пересчёт | `tools/import_donor.py` (GLB → OBJ), `tools/donor_frame.py` (оси и выравнивание), `tools/ship_donor.py` (раскладка в `assets/model`), `tools/pack_pbr.py` (металл/гладкость) |
| Материалы | 4 шт.: `Su34_Airframe` (4K basecolor + normal + 2K металл/гладкость), `Su34_Glass` (прозрачный), `Su34_HUD` (зелёный, с эмиссией), `Su34_Lights` (эмиссия) |

Важно: при пересчёте осей из glTF в Unity (`+x нос / +y верх / +z правый борт`
→ `+z нос`) две оси меняются местами, то есть это отражение. Поэтому
`donor_frame.py` разворачивает обход вершин у каждой грани — иначе нормали
смотрят внутрь и в Unity модель выворачивается наизнанку. Проверка знака
объёма: у планера он положительный.

Ниже — описание **процедурной** модели, которая остаётся запасным вариантом:
билдер переключается на неё одной константой `ModelFileName = "su34.obj"`.

## Геометрия: считается с чертежа, а не «на глаз»

Модель больше не набирается из прикидок. `trace_blueprint.py` обводит
`docs/refs/bp-1-three-views.png` (лист «вид сверху + вид сбоку + вид спереди»),
калибрует его и пишет таблицы в `blueprint_data.py`:

| Что | Откуда | Калибровка |
|---|---|---|
| Полуширина фюзеляжа | вид сверху | масштаб 0.05065 м/пиксель |
| Верх фюзеляжа и низ (брюхо) | вид сбоку | тот же масштаб, y = 0 по низу брюха |
| Передняя/задняя кромка крыла | вид сверху | LE 43.1°, TE: 1.1° до излома, 16.5° на носке |
| ПГО | вид сверху | LE 52.7°, корень z +3.92, конец z +1.98 |
| Стабилизатор | вид сверху | LE 46° |
| Киль (корень/верх, кромки) | вид сбоку | LE 37°, верх на 4.80 м, разнос 4.08–4.18 м |
| Фонарь (крона) | вид сбоку | купол 2.92 м над брюхом |
| Передняя часть (ширина, «плечи») | вид спереди | фюзеляж 2.3 м, фонарь 2.04 м, гондолы 1.18–3.40 м |
| Нижний край гондол | вид спереди | 0.00 м — по нему калибруется низ модели |

Проверка — не «похоже», а цифры: `overlay.py` проецирует OBJ ортогонально в
масштаб чертежа и сравнивает маски пиксель в пиксель.

```
top    IoU  94.3%   missing 2.76 m2   extra 4.59 m2
side   IoU  91.9%   missing 0.98 m2   extra 2.82 m2
front  IoU  75.0%   missing 2.43 m2   extra 5.11 m2
front* IoU  76.7%   (вертикальный масштаб подогнан отдельно: лист bp-3
                    сжат по высоте примерно на 5 %, судить по форме)
```

Вид спереди снимается с нижней части `docs/refs/bp-3-livery.png` (масштаб по
размаху 0.03443 м/пиксель, центр x = 284, низ 956 строки) и сравнивается с
ортогональной проекцией модели на плоскость XY.  Лист нарисован с разным
масштабом по осям, поэтому `overlay.py` печатает две цифры: `front` — честное
наложение в масштабе размаха, `front*` — то же с отдельным вертикальным
масштабом, то есть оценка формы, а не пропорций листа.  Для модели важна
вторая; первая штрафует за ошибку чертежа.  Табличные полуширины по высоте
печатает `front_profile.py` — их и надо сверять с полосами, снятыми с листа
вручную.

Остаток — полоса 1–2 пикселя по передним кромкам (толщина линии на чертеже) и
концевые обтекатели. Картинки: `docs/model/su34_overlay.png` (сверху и сбоку) и
`docs/model/su34_overlay_front.png` (спереди): оранжевый — не хватает объёма,
синий — лишний, серый — совпало.

* Оси — юнитивские: **+X вправо, +Y вверх, +Z нос**. Метры, 1:1.
  **y = 0 — низ брюха**, земля на y = −1.32. Габариты: размах 14.76, высота
  6.12, длина планера 23.24 м (23.88 с ПВД).
* Фюзеляж — лофт по 150 станциям (z, полуширина, верх, низ, показатель
  суперэллипса), 56 точек в кольце. Нос (z >= 9.6) — отдельная часть с
  материалом обтекателя.
* `skin_top_y(z, x)` — высота верхней поверхности фюзеляжа в точке. Ей
  пользуются и вырез кабины, и борт «стакана», и низ фонаря: поэтому щелей
  между остеклением и обшивкой нет.
* Крыло, ПГО, кили, стабилизаторы — `lifting_surface` по профилю NACA;
  кромки — функции `wing_le/wing_te` (у крыла задняя кромка с изломом, как на
  чертеже). Руль/элерон/закрылок сидят **внутри** контура, на задней кромке,
  поэтому не торчат за обвод.
* `Mesh.orient(part, ref)` разворачивает треугольники наружу относительно
  опорной поверхности, поэтому за порядком обхода вершин следить не нужно.
* Превью рисует свой растеризатор с **двусторонним затенением**: тонкие
  поверхности (гребёнка «стелс» на носке, рамы фонаря) не пропадают под
  скользящими углами. Не добавляйте туда отсечение по толщине — появятся
  полосы.

## Кабина: два места бок о бок

Настоящий Су-34 — не тандем. Пилот слева, штурман-оператор справа, плечом к
плечу, общая приборная панель на двоих. В модели это сделано так:

| Что | Значение |
|---|---|
| Проём фонаря | z = 4.25 … 7.25 |
| Полуширина борта (порог) | x = ±0.96 |
| Пол кабины | y = 1.22 |
| Кресла | x = ±0.42, центр чашки z = 5.55 |
| Приборная панель | z = 6.62 … 6.95 |
| ИЛС | только у левого кресла, x = −0.42 |
| МФД | по два на каждого: x = ±0.30 ± 0.14 |

* «Стакан» кабины — открытый сверху лоток: стенки на x = ±0.62 поднимаются
  ровно до `skin_top_y(z, 0.62)`, то есть до реального борта обшивки. Сверху
  надевается остекление, низ которого считается по той же функции — стык
  закрыт тонким комингсом `Su34_CanopySill`.
* Фонарь — лофт по `CANOPY_SECTIONS` (z, высота гребня): лобовое стекло
  поднимается от 1.22 м на z = 7.85 до 1.62 м в середине. Рамы: арка
  лобового стекла, арка за креслами и центральная балка.
* Сзади фонарь переходит в гаргрот (`Su34_CanopyFairing`), спереди — в
  обшивку носа; фюзеляж между ними вырезан по линии борта, а не «прямоугольником».
* Кресла — чашка, спинка, подголовник и боковые рельсы (материал
  `Su34_Cushion`), между ними центральная консоль, по бортам пульты с РУДами,
  ручки и педали. Всё это отдельные объекты, их удобно двигать под
  VR-интерактив.

**Якоря экипажа.** В Unity-билдере (`Su34BundleBuilder.AddCrewAnchors`)
создаётся пустой объект `Su34_CrewSeats` с дочерними
`CrewSeat_Pilot (−0.30, 1.15, 6.40)` и `CrewSeat_WSO (+0.30, 1.15, 6.40)`.
Координаты совпадают с генератором: если сдвинете кресла в модели, поправьте
и билдер. Это наши маркеры (камеры, логика миссий, будущая кабина); реальные
места игроков — это посадочные места донора, их двигает `AlignCrewSeats`.

**Два игрока: как это работает в VTOL VR.** Второй слот выдаётся не «моду», а
префабу самолёта: игра смотрит, есть ли на нём два посадочных места. Поэтому
двухместные — только AH-94, T-55 и EF-24G (все DLC, все тандемом), и именно
поэтому мод AH-6 требует AH-94. Мы делаем то же самое, но на реактивном
доноре:

| Донор | Мест | Роль второго |
|---|---|---|
| EF-24G (приоритет 1) | 2 | WSO/EWO: радар, TSD, целеуказание — как штурман Су-34 |
| T-55 (приоритет 2) | 2 | инструктор/второй пилот, полные органы управления |
| F/A-26B (откат) | 1 | второго места нет |

`AlignCrewSeats()` ищет в префабе донора места экипажа двумя способами:
компоненты, в имени типа которых есть `Seat`, и поля-ссылки с именами
`seat/pilot/crew/wso/ewo/gunner/instructor` (одиночные Transform, GameObject
или массивы/списки). Дальше:

1. общий предок найденных мест (обычно корень кабины донора) сдвигается так,
   чтобы переднее место попало на наше левое кресло — иначе на коротком
   фюзеляже (T-55 — 13.4 м) приборы донора остались бы в носу, далеко перед
   экипажем;
2. места сортируются по z (нос — первым) и переносятся на наши координаты:
   переднее → пилот слева, заднее → штурман справа.

В `build_report.txt` пишется каждое найденное место, откуда оно взято, куда
переехало и на сколько сдвинулась кабина. Если у вашей версии игры другая
иерархия, по этому отчёту видно, что искать. Крайний случай — задать пути
вручную: `SeatPathPilot` / `SeatPathWso` в билдере.

Что учесть:

* DLC-код мод не копирует, используется только префаб — как в AH-6.
* Без DLC билдер откатывается на F/A-26B: самолёт летает, но второе место
  недоступно, и в лог пишется предупреждение.
* В **редакторе миссий** у спавна игрока надо выбрать **2 slots** — по
  умолчанию стоит один, и именно из-за этого «второй игрок не заходит».
* В одиночной игре место переключается как в T-55 (если донор это умеет).
* Кабина донора внутри нашей оболочки пока остаётся видимой: это единственный
  источник работающих МФД и переключателей (см. следующий раздел).

## Свои MFD, ИЛС и переключатели

Сейчас в модели панель, МФД и ИЛС — геометрия. В игре картинку на МФД рисует
компонент самой игры, поэтому в билдере кабина донора (EF-24G/T-55/F/A-26B)
пока остаётся **видимой и рабочей**: оттуда берутся интерактивные приборы.
Порядок работ, чтобы заменить её полностью:

1. вытащить из префаба донора объекты МФД/ИЛС/РУД (`1 - Dump donor hierarchy`
   пишет список в `build_report.txt`);
2. перенести их на наши координаты панели (см. таблицу выше);
3. только после этого убрать `cockpit/mfd/hud/stick/...` из
   `KeepVisibleKeywords` в `Su34BundleBuilder.cs` — иначе останутся две
   кабины одна в другой.

## Взять геометрию Су-34 из чужого NPC-пака

Пакеты NPC в Мастерской VTOL VR — обычные asset bundle. Меш оттуда можно
посмотреть и сохранить у себя:

```bash
pip install UnityPy        # нужен Python 3.9+

# где вообще есть Су-34 среди подписанных паков
python tools/su34_model/extract_from_bundle.py --scan \
    "/path/to/steamapps/workshop/content/3018410"

# список мешей и текстур в папке пака (Steam: workshop/content/3018410/<id>)
python tools/su34_model/extract_from_bundle.py --list \
    --bundle "/path/to/steamapps/workshop/content/3018410/1234567890"

# экспорт меша с именем, содержащим "su-34", в OBJ + текстуры рядом
python tools/su34_model/extract_from_bundle.py --mesh su-34 \
    --bundle "/path/to/.../1234567890" --out assets/model/su34_imported.obj
```

* По умолчанию скрипт **отражает X** (Unity — левая система, OBJ — правая).
  Если модель окажется «вывернутой», добавьте `--no-flip-x`.
* `--scale 0.01` пригодится, если автор пака моделировал в сантиметрах.
* Текстуры (если они есть у меша) кладутся в `<out dir>/textures/`.
* Скрипт ничего не качает из интернета и не обходит защиту: он читает файлы,
  которые уже лежат у вас на диске.

**Правовая сторона.** Свою копию пака вы используете локально; в Мастерскую
мод с чужим мешем выкладывать можно только с разрешения автора — поэтому в
описании мода указывайте автора исходного пака (вы это и планировали). Если
разрешения нет — остаётся процедурная модель из этого репозитория, она
целиком наша.

## Чужая модель: проверка и нормализация

Прежде чем модель попадёт в Unity, прогоните её здесь:

```bash
python3 tools/su34_model/import_check.py incoming.obj
python3 tools/su34_model/import_check.py incoming.obj --up z --forward -y \
    --auto-scale --center-x --out assets/model/su34_imported.obj
```

Скрипт показывает объекты, треугольники, материалы, UV, габариты, какая ось
длиннее и куда смотрит нос (по сечению на концах), определяет сантиметры/
миллиметры по размеру, считает вырожденные треугольники и «иглы», проверяет,
разбиты ли рули/закрылки/створки шасси на отдельные объекты. С `--out`
переписывает OBJ в оси VTOL VR (+Z нос, +Y верх, метры), не трогая UV и
материалы. FBX/glTF этот скрипт не читает — они годятся для Unity-стороны.

## Свой hi-poly меш (альтернатива)

1. **Лицензия.** CC-BY, купленная или заказанная модель. Ассеты, выдранные из
   War Thunder / DCS, использовать нельзя.
2. **Масштаб и оси.** Длина ~23.3 м (у нас 25.3 с ПВД), размах 14.7 м. В
   Blender: `Forward = -Z`, `Up = Y`, `Apply Transform`, масштаб 1.0. В Unity
   нос смотрит в +Z.
3. **Разрезка поверхностей.** Каждый руль/закрылок/створка — отдельный объект
   с origin на оси вращения:

   | Объект | Ось |
   |---|---|
   | `aileron_L/R`, `flap_L/R` | X |
   | `elevator_L/R` | X |
   | `rudder_L/R` | Y |
   | `canard_L/R` | X |
   | `gear_door_*` | Z |

4. **UV и материалы.** Один атлас 4K на весь самолёт, PBR-материал
   (Metallic/Smoothness). Имена материалов начинайте с `Su34_`.
5. **Импорт.** `Assets/Su34/Models/Su34_HighPoly.fbx`, Model → Scale Factor 1,
   Read/Write Enabled, Generate Lightmap UVs, Rig → None.
6. **Подмена в билдере.** В `Su34BundleBuilder.AttachModel` замените

   ```csharp
   var modelAsset = AssetDatabase.LoadAssetAtPath<GameObject>(ModelObjPath);
   ```

   на путь к вашему префабу (или создайте префаб из FBX и поменяйте
   `ModelObjPath`).

## Куда это встаёт в игре

`Su34_Visual` — дочерний объект под корнем префаба. Всё «мясо» (масса,
коллайдеры, шасси, кабина, MFD, оружие) остаётся от донора (EF-24G / T-55 /
F/A-26B), поэтому
самолёт сразу летает, стреляет и садится на палубу. Внешние рендереры донора
билдер отключает. Наша кабина — геометрическая оболочка: кресла, панель, МФД,
ИЛС видны, но интерактив пока берётся от донора (см. раздел выше).


## Что сделано по детализации (после правок «до максимальной точности»)

* **Фюзеляж** — единый лофт по 234 станциям, снятым с чертежа. Появилось
  настоящее сечение Су-34: широкая плоская палуба над двигателями (2.05 м
  полуширины на высоте 1.45 м) с жёстким переломом к узкому гребню (1.39 м на
  1.65 м), и два мотогондолы-туннеля снизу, которые и дают низ брюха. До этого
  корпус был узкой трубой, поэтому вид спереди не сходился ни по килям, ни по
  гондолам.
* **Киели** вынесены на край палубы (x = ±2.00…2.14): на листе bp-3 они стоят
  ровно там (полосы на ±2.12 м), раньше модель держала их на ±1.3.
* **Крыло** — задняя кромка переделана по замеру: при z = −4.6 крыло на листе
  есть только снаружи x = 3.0, при z = −5.0 — снаружи x = 4.5; это одна прямая
  от (2.33, −4.42) до законцовки, наклон 15.2°. Старый излом на x = 5 держал
  корневую хорду на 0.7 м длиннее, из-за чего вид сверху «пух» в районе z = −5.
* **Фонарь** — не одно стекло: переднее стекло, два боковых сегмента, рама по
  низу, дуга, центральная балка, задняя дуга и обтекатель-гаргрот. Рама —
  отдельный материал `Su34_CanopyFrame` с камуфляжной текстурой, стекло —
  `Su34_Glass` (alpha 0.38).
* **Кабина** — два рабочих места бок о бок: каркасные кресла с подушками,
  подголовником, ремнями и скобой катапульты, изогнутая приборная панель с
  утопленными МФД и трёхстрелочным блоком, боковые консоли с рядами тумблеров,
  центральный пьедестал с РУДами, самолётное управление, педали, ИЛС у левого
  пилота, обшивка стен и потолка, дуги каркаса изнутри.
* **Шасси** — колёса с профилем (скруглённые плечи, протектор, диск, тормозной
  диск, заглушка, 6 болтов), телескопические стойки (наружная труба + шток),
  подкос, полувилка, ножницы, створки и щиток на носовой стойке.
* **Сопла** — 14 перекрывающихся лепестков, тёмное кольцо, внутренний конус,
  подогретый металл (`Su34_NozzleHot`).
* **Зуб (beaver tail)**, гребень, воздухозаборники с обечайкой и тёмным
  каналом, ПВД, приёмник ОЛС, антенны, тормозной щиток, надписи и звёзды.

## Раунд «по скриншотам» (нос, фонарь, камуфляж)

* Нос перетрассирован в плане по обводу листа: 0.95 м на z = 7.5, 0.83 на 9.5,
  0.60 на 10.4, 0.44 на 11.0 — вместо плавного конуса получился «утиный»
  излом; скуловые гребни (`Su34_Chine_L/R`, z = 7.4…11.3) вынесены наружу на
  0.105 м и образуют острую кромку.
* Фонарь: superellipse-сечение (плоский верх, вертикальные боковые стёкла), добавлены A-образные стойки козырька (стекло делится на центральную
  и две боковые панели), арки утолщены до 58 мм, по кромке стекла пущен
  чёрный резиновый профиль, рама затемнена, стекло тонировано (alpha 0.46).
* Камуфляж переделан: пятна 0.4–0.8 м вместо 1–2 м, контраст снижен до ±10 %,
  границы размыты — на рендере больше не читается как «камуфляж из ведра».
* В воздухозаборниках появились диски вентилятора с коком и 16 лопаток —
  спереди видно двигатель, а не чёрную дыру.
* Ниши шасси: вместо белых створок, торчащих в поток, — тёмный колодец внизу
  гондолы и створка на стойке в цвет камуфляжа.
* `apply_box_uv` — плитка 2.6 м; текстуры перегенерированы.
* Верх фюзеляжа над кабиной стал плоской палубой с жёсткими «плечами»
  (показатель 4.2 вместо 2.9) — сглаженные углы убраны.
* Камуфляж двухцветный с жёсткой ватерлинией (`apply_waterline`): тёмный верх
  (74, 86, 99), светлый низ, стык по нормали и высоте грани — как на реальном
  борту, а не однотонное пятно по всему самолёту.

## Что осталось (открытые дефекты)

* В превью на переднем стекле видна сетка — предположительно самопересечение
  квадов лофта стекла; в Unity проверить на месте (материал там другой).
* Нос в плане перетрассирован по обводу листа (0.44 м на z = 11.0, 0.60 на
  10.4, 0.83 на 9.5) и получил резкий «утиный» излом по скулам, но в 3/4 вид
  ещё читается конусом — нужна более плоская нижняя палуба передней части.
* Гондолы в виде спереди уже́, чем на листе: лист даёт ±2.6 м на высоте 0.65 м,
  модель — сплошную плиту ±1.8 м.  Вынос гондол наружу пробовал — IoU падает,
  поэтому вопрос открыт.
* Нет расшивки (панельных швов и заклёпок) отдельной геометрией — только
  текстура.
* Пилоны без подвесного вооружения; ракеты/бомбы будут ставиться средствами
  VTOL VR, но визуальных моделей пока нет.
* `front` (честный IoU) держится около 75 % из-за разного масштаба осей на
  листе bp-3 и из-за того, что на нём нарисовано шасси; по форме — 76.7 %.
* Кабина внутри — рабочая двухместная компоновка (приборная панель, боковые
  пульты, два кресла), но без детализации реального Су-34: нет надписей,
  точных МФД, РУС/РУД по образцу.  Это следующий этап — заказчик просил делать
  кабину после внешней геометрии.
