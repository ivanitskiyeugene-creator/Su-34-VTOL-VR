# Unity: сборка самолётного asset bundle

Этот проект Unity нужен ровно для одного: превратить `assets/model/su34.obj`
в asset bundle `su34`, который читает мод. Всё остальное (код, полётная модель,
кабина, оружие) приходит из префаба VTOL VR, который вы экспортируете из своей
копии игры. Билдер предпочитает **двухместные** префабы — EF-24G, затем T-55 —
потому что только у них в игре есть второе посадочное место; F/A-26B остаётся
запасным вариантом.

> **Важно.** Файлы игры вы экспортируете сами, на своём компьютере. В репозитории
> нет ни одного файла из VTOL VR — только наш собственный OBJ-меш.

## 1. Один раз: Unity нужной версии

VTOL VR собран на Unity 2020.3.x. Точную версию видно:

* в `player.log` (третья строка: `Initialize engine version: 2020.3.49f1`), или
* в `ProjectSettings/ProjectVersion.txt` после экспорта игры AssetRipper'ом.

Сейчас игра (1.13.4f1) и модлоадер 6.10.x идут на **2020.3.49f1** — её и ставьте
(changeset `18249dd5551b`, последний патч ветки; ставится рядом с любой другой
версией Unity и ничего не ломает). Прямая ссылка для Unity Hub:
`unityhub://2020.3.49f1/18249dd5551b`, страница —
https://unity.com/releases/editor/whats-new/2020.3.49f1. Дополнительные модули
(Android, WebGL, IL2CPP) не нужны: Windows-редактор сам собирает под Windows.
Если в `player.log` окажется другой патч 2020.3 — ставьте ровно его: бандл,
собранный более новым патчем, игра может не принять.

## 2. Один раз: экспорт игры в Unity-проект

1. Скачайте **AssetRipper** (https://github.com/AssetRipper/AssetRipper/releases),
   запустите `AssetRipper.GUI.Free.exe`.
2. Перетащите в него папку `...\steamapps\common\VTOL VR` целиком.
3. `Export > Export All Files`, выберите пустую папку.
4. После экспорта:
   * удалите папку `AuxiliaryFiles`;
   * перенесите содержимое `ExportedProject` в корень вашей папки проекта;
   * в `Assets/Plugins` удалите все DLL движка Unity и SteamVR;
   * удалите шейдер `Hidden_UIElements_EditorUIE`;
   * через Package Manager поставьте `TextMeshPro`, `XR Plugin Management`,
     `2D Sprite`, `Input System`;
   * из SteamVR Plugin (Asset Store) импортируйте плагин, **сняв галочку** с
     `JSON.NET / Valve.Newtonsoft.Json.dll`.
5. Скопируйте в `Assets/Plugins` DLL из `VTOL VR/VTOLVR_Data/Managed`:
   `Assembly-CSharp.dll`, `Assembly-CSharp-firstpass.dll`, `0Harmony.dll`,
   `ModLoader.Framework.dll` (последние две — из `@Mod Loader/Managed`),
   `Facepunch.Steamworks.Win64.dll`, `Unity.TextMeshPro.dll`.
6. Откройте проект в Unity. Первый запуск долгий, это нормально.

Если Unity ругается на `ControlMapper.cs` — в официальной инструкции
(https://vtolvr-mods.com/docs/vtolvr/asset-ripper/) написано, какую строку
закомментировать.

## 3. Подключить файлы этого репозитория

Проще всего — скриптом из корня репозитория, он делает всё за вас:

```powershell
.\tools\prepare_unity_project.ps1 -Export "D:\RipperExport" -Project "D:\VTOLVR_Project"
```

Вручную:

1. Скопировать папку `unity/Assets/Su34` в `Assets/Su34` проекта.
2. Скопировать `assets/model/su34_donor.obj`, `assets/model/su34_donor.mtl` и
   `assets/model/textures/*.png` в `Assets/Su34/Models/` и
   `Assets/Su34/Models/textures/`.
3. Дождаться импорта OBJ (он появится как префаб с мешами).

Если модель уже лежит в `Assets/Su34/Models`, билдер её не трогает и пишет
`model already imported` — проект можно держать отдельно от репозитория.

## Текстуры: что и сколько

Вся внешность — один атлас на 4096 x 4096: камуфляж, надписи, звёзды, панельные
швы, интерьер кабины. Плюс нормали и упакованная карта «металл/гладкость».

| Файл | Размер | Что это | В видеопамяти (DXT + мипы) |
|---|---|---|---|
| `donor_basecolor.png` | 4096x4096 | цвет, весь атлас | ~11 МБ |
| `donor_normal.png` | 4096x4096 | нормали (швы, клёпка) | ~22 МБ |
| `donor_metalsmooth.png` | 2048x2048 | R = металл, A = гладкость | ~6 МБ |
| итого | | | **~39 МБ** |

Плотность: у планера один тексель приходится примерно на 5.6 мм поверхности,
у кабины — на 3 мм, у фонаря — меньше 1 мм. Для кастомного самолёта это много:
в ваниле VTOL VR внешние текстуры 2K, и на расстоянии 5–10 м от кабины 2K уже
мылит панельные швы.

**Зачем 4K, если это VR.** Модель одна и грузится один раз: 39 МБ видеопамяти
на самолёт — не проблема даже на 8 ГБ. А вот потерять резкость швов и мелких
надписей на фюзеляже легко: при 2K тексель становится 11 мм, и на крыле,
которое пилот видит с двух метров, это заметно.

**Если нужно ужать** (слабый VRAM, большой размер бандла):

1. в `Assets/Su34/Editor/Su34Materials.cs` поменять
   `TextureSize = 4096` на `2048` — Unity переимпортирует обе 4K-карты;
2. то же для упакованной карты: `tools/pack_pbr.py`, `SIZE = 2048` -> `1024`,
   затем `python tools/pack_pbr.py`.

Итог: ~14 МБ вместо ~39 МБ, тексель на планере 11 мм.

Импорт-настройки (`Tools/Su-34` вызывает их сам при сборке): размер = `TextureSize`,
нормаль импортируется как Normal Map, металл/гладкость — как линейная карта
(без sRGB, иначе материал получается пересвеченным), мипы включены, анизотропия 4.
Без этого Unity по умолчанию срезал бы текстуры до 2048 и импортировал нормаль
как цветную картинку.

## 4. Сборка

В меню Unity появятся пункты **VTOL VR / Su-34**:

| Пункт | Что делает |
|---|---|
| `0 - Copy model + textures` | копирует `assets/model` в `Assets/Su34/Models` (сборка делает это сама) |
| `0b - Check setup` | проверяет префаб-донор и модель и печатает `crew seat rigs` |
| `1 - Dump donor hierarchy` | пишет в корень проекта `Su34_donor_hierarchy.txt` со всеми объектами донора — по нему видно, какие части кабины оставить |
| `2 - Build prefab + asset bundle` | собирает `Su34.prefab`, бандл `su34` и копирует его в `mod/` этого репозитория |
| `3 - Dump flight model to a file` | пишет `Su34_flightmodel.txt` в корень проекта: масса, тяга, площадь крыла, лимит перегрузки и все похожие поля донора. Нужен, если самолёт летит не так, как ожидалось |
| `3 - Build DLL and install into the game` | запускает `tools/build.ps1 -Deploy`: собирает `Su34Mod.dll` и ставит всё в `@Mod Loader/Mods/Su-34` |

Префаб-донор ищется автоматически в порядке приоритета **EF-24G → T-55 →
F/A-26B**: сначала по прямому пути `Assets/Resources/vehicles/<имя>.prefab`,
затем точным именем префаба, затем любым префабом с «vehicle» в пути.
Выбранный путь и число посадочных мест печатаются в консоль. Принудительно
задать донора можно константой `DonorPrefabOverride`.

После `2 - ...` в `mod/` появятся:

```
mod/su34               <- asset bundle (его и грузит мод)
mod/build_report.txt   <- что скрыто, что оставлено из кабины донора
```

Если Unity пишет, что не нашёл донора — откройте `Su34_donor_hierarchy.txt`
(или поиск в Project) и задайте путь константой `DonorPrefabOverride` в
`Assets/Su34/Editor/Su34BundleBuilder.cs` (пустая строка = автопоиск).

## Кабина: что приезжает из донора само

Руками ничего расставлять не нужно — МФД, РУС, РУД, галетники, HUD и все
остальные интерактивы уже лежат в префабе донора, с готовой логикой, сетевой
синхронизацией и привязкой к рукам. Билдер их переносит:

1. **Станции делятся по креслам.** Любой ванильный двухместный самолёт —
   тандем, то есть в префабе две полные станции друг за другом: передняя
   (пилот: HUD, РУС, РУД, МФД) и задняя (штурман / инструктор, свои МФД и
   рычаги). Билдер обходит группу кабины сверху вниз, определяет, к какому
   креслу ближе каждый объект, и сдвигает каждую станцию на своё кресло —
   переднюю на левое, заднюю на правое. Ничего не копируется, поэтому не
   появляется ни одного дубликата сетевых компонентов.
2. **Кресла переезжают** на координаты, снятые с меша Су-34
   (`-0.52 / +0.52`, `y 1.45`, `z 6.30`), и оборачиваются в маркеры
   `Su34_SeatPilot` / `Su34_SeatWso`.
3. **Донорская мебель прячется**: сиденья, фонарь и внутренняя обшивка
   донора отключаются как рендереры (сами компоненты и логика остаются), иначе
   две кабины наложились бы друг на друга. Руки, перчатки и шлем никогда не
   прячутся.

Что это значит на практике: в кабине появятся **две станции** — слева
пилотская, справа та, что была у донора сзади. У EF-24G задняя станция — место
оператора РЭБ, у T-55 — инструктора. Их приборы и экраны показывают то, что
показывали в доноре; переучивать их на «штурманские» — отдельная работа, и
делать её имеет смысл только после того, как ты увидишь кабину в игре.

В `build_report.txt` будет строка вида:

```
cockpit split into stations: 37 groups moved, 2 already in place
station pilot (left): Cockpit/FrontPanel by (-1.84, 0.00, -3.10)
```

По ней видно, что и на сколько уехало. Если станция уехала не туда — присылай
отчёт, поправлю радиус или список ключевых слов.

## Лётная модель

Префаб наследует массу, тягу и аэродинамику донора (EF-24G весит меньше и
тянет иначе), поэтому `Su34FlightModel.cs` при сборке перезаписывает их
реальными числами: пустая масса 22 500 кг, тяга 264 780 Н на форсаже и
161 810 Н без, крыло 62 м², размах 14.7 м, предел +7 g.

То же самое повторяется в рантайме (`src/Su34Mod/FlightModel.cs`), потому что
игра пересоздаёт самолёт при каждом спавне и смене подвесок. Числа берутся из
`mod/su34.cfg` — файл рядом с DLL, правки применяются после перезапуска миссии,
бандл пересобирать не нужно.

Все изменения пишутся в `Output.log` блоком `--- Su-34 flight model ---`:
какое поле найдено, что было, что стало. Если поле не нашлось — там будет
строка `no field with 'thrust' in the name` и подобное; тогда пришлите лог,
я подгоню имена.

## Как это устроено

`Su34BundleBuilder`:

1. грузит префаб донора (EF-24G / T-55 / F/A-26B; в нём уже есть полётная
   модель, шасси, оружие, MFD, VR-интерактивы и кабина);
2. переименовывает его в `Su34`, добавляет `ExternalVehicleInfo` и заполняет
   имя/описание/никнейм;
3. вставляет под корень наш `su34.obj` (`Su34_Visual`);
4. отключает у донора **внешние** рендереры (фюзеляж, крылья, шасси-меши),
   оставляя всё, что похоже на кабину (`cockpit`, `seat`, `mfd`, `hud`,
   `canopy`, `panel`, `switch`, ...). Полный список — в `build_report.txt`;
5. ищет у донора посадочные места (`Seat`-компоненты и поля с именами
   `seat/pilot/crew/wso/...`), сдвигает общий корень кабины донора к нашему
   фонарю, затем сортирует места по z и переносит на наши кресла: переднее —
   пилот слева, заднее — штурман справа (`AlignCrewSeats`);
6. сохраняет префаб, помечает его в бандл `su34` и собирает
   `StandaloneWindows64`.

Такой путь даёт полностью рабочий самолёт: кликабельная кабина, оружие,
радар, HUD, посадка на палубу — всё от донора, а снаружи и в анфас — Су-34.

## Какая модель используется

`Su34BundleBuilder.ModelFileName = "su34_donor.obj"` — это модель **bohmerang**
(Sketchfab, свободная загрузка; кредит обязателен, см. `docs/АТРИБУЦИЯ.md`).
33 582 треугольника, PBR-текстуры 4K, узлы: планер, фонарь, кабина, HUD,
стёкла приборов и три варианта шасси. Лежит в `assets/model/`, оттуда её и
копирует билдер.

Процедурная модель `su34.obj` осталась запасным вариантом: чтобы вернуться на
неё, достаточно поменять `ModelFileName` на `"su34.obj"` — остальной код
подхватит новый файл через `ModelObjPath`.

Если захотите поставить свою модель:

1. возьмите Su-34 с нормальной лицензией (CC-BY / купленную / заказанную у
   3D-художника) — **не** выдранную из War Thunder или другой игры;
2. импортируйте FBX в Unity, поверните носом по +Z, масштаб 1:1 в метрах
   (длина 23.3 м, размах 14.7 м), низ фюзеляжа на y = 0;
3. вынесите рули/закрылки/шасси в отдельные объекты, если хотите анимацию;
4. положите префаб в `Assets/Su34/Models/` и в `Su34BundleBuilder.AttachModel`
   замените загрузку OBJ на свой префаб (одна строка).

Инструкция по подготовке меша (разрезка рулей, шарниры, UV) —
`docs/МОДЕЛЬ.md`.
